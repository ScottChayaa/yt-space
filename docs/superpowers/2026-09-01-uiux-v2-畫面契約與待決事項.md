## 這份文件是什麼

這是開發計畫的**前一步**，不是計畫本身。

規格與 UI 原型各自都沒問題，但兩者矛盾的地方有 11 處是**二選一**的——不是「加預算就能兩個都要」，
而是選了 A 之後 B 的驗收條目會直接不成立。任務怎麼切、切幾個、誰卡誰，完全取決於這些選擇。
先猜再排，猜錯的不是一兩個任務，是整段白做。

**這份文件本身就適合帶進會議**：第一節是後端要實作的資料契約，第二節是所有差異與留白的評估欄，
第三節把三個最大的互斥項展開成選項，第四節是 11 個可以用「選項編號」回答的問題。

## 一、畫面契約

標 ★ 的項目，表示**規格第四節的資料模型或第十一節的十四個階段裡沒有直接對應**，需要新欄位、新端點或新彙總。

### 1. 登入

> 這一頁是否存在，取決於 Q-1。以下是「站內登入頁」成立時的契約。

| 面向 | 內容 |
|---|---|
| 顯示 | 產品名、一句 tagline、Google 按鈕、條款連結。**無任何資料來源** |
| 動作 | 登入成功 → 取得 `owner_id`（值為 email），建立 session |
| 狀態 | 登入中（按鈕鎖住＋轉圈）／未登入攔截（掛在 `<head>`，不可先閃一下內容）／已登入時開登入頁直接重導首頁／登入後回到原本要去的頁 |
| 量級 | — |

### 2. 首頁 `/`

**顯示欄位 → 資料來源**

| 畫面元素 | 來源 |
|---|---|
| 月份標題 | `shot.event_date` 前 7 碼分組 |
| 月份標籤列 | `GET /api/facets?ym=` → `tag.name` 與 `shot.place` 混排（規格第六節） |
| 縮圖 | `shot.thumb_key` → R2 單格 webp，`<img loading="lazy">` |
| **卡片描述** | `shot.description`；空值顯示灰字「還沒有描述」。★ 首頁清單的回傳欄位需加入 `description` |
| **每月欄數（1 張／2–4 張／5+ 張）** | ★ 需要「該月 shot 總數」。keyset 分頁在捲完該月之前拿不到總數；`facet_month_agg` 也不能用（一張圖有 3 個標籤就被計 3 次），需要另一張以月為單位的 shot 計數或新端點 |
| 時間篩選狀態列 | 前端狀態 ＋ `upTo` 查詢參數 |

**動作 → 語意**

| 動作 | 語意 |
|---|---|
| 點縮圖 | 開 Lightbox。左右滑動範圍＝**目前顯示中的清單**（跨月，非單月） |
| 點月份標籤 | 導向查詢頁，帶入 facet 條件 ＋ `upTo=該月`，**直接顯示結果**（跳過條件頁） |
| 日曆鈕選月 | `GET /api/shots?upTo=YYYY-MM`，重取第一頁 |

**狀態**：空圖庫／篩選後為空（附「清除時間篩選」）／載入中／★ **縮圖 404**（R2 物件遺失時該格的外觀，規格未定義，見 D-18）

**量級**：一次 50 筆 keyset（規格第八節）。每筆 JSON 約 250 B（含 description、place、tags）→ 約 12 KB；縮圖 50 × 5.9 KB ≈ 295 KB，lazy 分批載入。

### 3. Lightbox

| 顯示 | 來源 |
|---|---|
| 大圖 | `shot.thumb_key`（320×180 放大，`object-fit: contain`） |
| 描述／地點／標籤／日期／影片標題 | `shot.description` / `place` / `shot_tag` / `event_date` / `video.title` |
| **「第 N / 共 M 張」** | ★ M ＝目前清單長度。清單尚未載完時 M 未知，需回傳該分組總數，或改為只顯示「第 N 張」 |

| 動作 | 語意 |
|---|---|
| 左右滑動 | 純前端，範圍＝進來時的清單 |
| 【影片播放】 | 導向 `/v/{videoId}?t={at_sec}`（手冊寫【播放這一段】，見 D-15） |
| 【加入分類】 | `GET /api/folders` 取樹 ＋ 勾選即 `POST`／`DELETE` `shot_folder`，**關閉即生效**（非提交式） |
| 【分享】 | Web Share API，內容 `https://youtu.be/{videoId}?t={at_sec}`；不支援時退回複製連結 |
| 【編輯】 | `PATCH /api/shots/{id}`，只送動過的欄位 |
| 【刪除】 | 硬刪除，連動：`shot_tag`、`shot_folder`、`facet_month_agg` 遞減、R2 物件；該片最後一張被刪時順帶刪 `video` 列 |

**狀態**：首次開啟的一次性滑動提示（記在本機）／刪除後自動滑下一張／刪到最後一張則關閉檢視器

### 4. 取圖 第一步：貼網址

| 顯示 | 來源 |
|---|---|
| 網址輸入框 | — |
| **「最近取過的影片」清單**（影片圖示＋標題＋日期＋張數，點了**直接進第二步**） | ★ 規格無此概念。可由 `video` 表推導（`owner_id` ＋ `added_at` 排序 ＋ 該片 shot 數），需新端點 |

| 動作 | 語意 |
|---|---|
| 【下一步】 | `GET /api/video/{videoId}` → metadata（Data API v3，`part=snippet,contentDetails,recordingDetails`）＋ `sb_spec` ＋ ★**該片已收藏的 `frame_index` 清單**（第二步要標示鎖定格） |

**狀態**：解析不出 videoId（就地錯誤，不換頁）／影片不存在或 private／**有影片但無 storyboard**（仍進第二步，只開放手動補圖）／**解析失敗**（同上，另記 `sb_probe(result='parse_failed')`）／已取過（提示「這支已收藏 N 張」）

**量級**：單筆。Data API `videos.list` 1 unit／次。

### 5. 取圖 第二步：挑畫面

| 顯示 | 來源 |
|---|---|
| 上方 iframe（sticky） | YouTube embed |
| 候選格（約 148 格） | `sb_spec` 解出 L3；CSS `background-position` **直連 `i.ytimg.com`**（無 CORS 只擋讀像素，不擋顯示） |
| 每格時間標籤 | `frame_index × interval` |
| 格子狀態 | 已選（紅框）／播放中（藍框）／**已收藏（灰＋鎖）** ← 來自第一步回傳的 `frame_index` 清單 |
| **收斂狀態列**「已收斂成 50 張候選，隱藏了 98 張相似畫面」 | ★ 見 D-2，**這是全案最大的可行性問號** |

| 動作 | 語意 |
|---|---|
| 點一下 | 切換勾選（整格都是點擊區） |
| 長按 0.5s | 播放器跳該秒，震動 15 ms |
| **每格右上角 ▶** | ★ 手冊新增（鍵盤與輔助技術的替代入口）。純前端 |
| 【全部選取】 | 全選／全不選，**不含已收藏的格子** |
| 【手動補圖】 | 相簿選圖 → 前端 canvas 縮至 480×270 webp → `PUT /api/thumbs`，key = `{videoId}/manual/{uuid}.webp`；`at_sec` 取自 `getCurrentTime()`（精確秒，不受取樣間隔限制） |
| 【只看已選】 | 純前端篩選 |
| 【下一步】 | 對每張勾選格：`GET /api/sheet?u=` 代理 → canvas 裁格 → WebP q75 → `PUT /api/thumbs`，key = `{videoId}/L{level}/{frameIndex}.webp`，**已存在則跳過**（天然去重） |

**狀態 / 降級**

- 無 storyboard → 空牆 ＋ 只開放手動補圖，**不當機**
- 只有 L2 沒有 L3 → 正常顯示 ＋ 提示畫質較低，存檔 key 為 `L2`
- ★ **sprite 圖本身回 403**（spec 解得出來、但簽章過期）→ 手冊第九節把「退回封面圖」列為驗收項，規格第七節只定義了「解不出 spec」那條路。這是兩種不同的失敗，見 D-18
- 已收藏的格子被點 → 手冊要求提示「這一格已經收藏過了」，規格寫「點擊無效」

**量級（後端評估的實際依據）**

- 148 格分佈在**約 17 張 L3 sheet**，直連顯示總量約 900 KB
- **若採進場即收斂**：這 17 張 sheet 必須全部經 `/api/sheet` 代理下載並解碼（Worker 請求 +17／次取圖），並在首屏前算完 148 次 dHash
- 若採規格原設計（按鈕觸發、只比對已勾選）：代理下載量等於使用者實際勾選所涵蓋的 sheet 數

### 6. 取圖 第三步：填資料

| 顯示 | 來源 |
|---|---|
| 4 欄縮圖網格 | 本批 shot 的暫存資料 |
| 綠點 | 該張已套用過圖資（前端狀態） |
| 抽屜：時間／地點／標籤／描述 | `event_date`（預設值鏈：`video.recorded_at` ?? `published_at`）／`place`（`SELECT DISTINCT place` 建議）／`tag` ＋ `aliases` 建議／`description`（允許留空） |
| `〈多個值〉` 佔位 | 勾選多張且該欄原值不一致 |
| **「將更新：地點、標籤　其他欄位維持各張原值」** | ★ 手冊新增的規則可視化。純前端，但它描述的正是下方的 API 語意 |

| 動作 | 語意 |
|---|---|
| 【套用到 N 張】 | `POST /api/shots/batch`，payload：`{ shot_ids: [...], fields: { 只帶使用者動過的欄位 } }`。**沒帶的欄位伺服器不得寫入**（各張維持原值）；標籤是整組覆蓋 |
| 分兩輪套用 | 第二輪不得影響第一輪已套用的張數 —— 由「只帶動過的欄位」保證 |
| 【未填的】 | 前端勾選所有無綠點者 |
| 【完成】 | 寫入 → 清本機草稿 → 導回首頁 → 捲到該 `event_date` 月份 → toast「已新增 N 張」 |

**狀態**：進場時「處理縮圖 12/18」進度（裁切在前端，必須在開著的分頁完成）／完成時若有未填「還有 N 張沒填資料，仍要完成嗎？」**提醒但不阻擋**／★ 按【✕】離開時詢問「保留草稿並離開／捨棄草稿」

**量級**：一批 18～148 張。batch payload 只有 id 陣列 ＋ 少數欄位，極小。

| 顯示 | 來源 |
|---|---|
| facet chips（**每個帶張數**，選取後除變色外加打勾） | `GET /api/facets?upTo=` → `facet_month_agg` 聚合，top-30 ＋「顯示更多」 |
| 描述關鍵字輸入 | — |

| ★「最近查詢」「沿用上次查詢」 | 原型有，規格無。目前存 localStorage |

| 動作 | 語意 |
|---|---|
| 標籤查詢 | 純 SQL：`place` 走 `shot.place = ?`，標籤走 `shot_tag` |
| 文字查詢 | 規格：Gemini Flash 解析 → `{places, tags, keywords}` → FTS5（trigram）；失敗退回規則式切分。★ 原型是純子字串比對，且**標籤模式與文字模式互斥不可並用**，規格則是合併查詢 |

### 8. 分類 `/folders`

| 顯示 | 來源 |
|---|---|
| 資料夾名稱 | `folder.name` |
| 張數（**含子孫層**） | 遞迴 CTE ＋ join 聚合（規格第六節評估為毫秒級） |
| **內容預覽（最多 4 張）** | ★ 需要每個資料夾的前 4 個 `thumb_key`。清單頁一次要 N×4 —— 這是列表端點的 N+1 風險點，作法待後端評估 |
| ★ 篩選字串 ＋ 4 種排序（名稱升／降、張數多→少、最近加入） | 原型有，規格無。「張數多→少」需先對全部資料夾算含子孫計數再排序 |
| 樹狀縮排（深度上限 5） | 規格要求；★ 原型目前是平面清單，mock 資料沒有子資料夾 |

| 動作 | 語意 |
|---|---|
| 新增（選父層）／改名／刪除 | 刪除＝連子資料夾與所有關聯一併刪，**圖本身不動**，確認框明示範圍 |
| 進入資料夾 | 上半子資料夾、下半本層的圖（`shot_folder(folder_id, added_at)` keyset） |
| 加入圖片 | **只從 Lightbox 的【加入分類】**；資料夾頁不提供挑圖介面 |

**狀態**：空資料夾（「還沒有圖片」）／完全沒有資料夾（空狀態帶【新增資料夾】按鈕）／已在第 5 層則 UI 阻擋再建子層

**量級**：每人資料夾數百列；預覽圖使列表回傳量 ×4。

### 9. 詳情 `/v/[videoId]`

| 顯示 | 來源 |
|---|---|
| 播放器 | `youtube.com/embed/{id}?start={at_sec}&autoplay=1&playsinline=1`，**不設 `end`** |
| **目前這一張的圖資**（描述、地點與標籤 chips、日期、影片秒數）＋【編輯這張的圖資】 | ★ 手冊第七節新增；規格只寫「點縮圖可就地編輯」 |

| 動作 | 語意 |
|---|---|
| 點縮圖 | 播放器跳該秒 |
| 長按／編輯鈕 | bottom sheet 就地編輯（與 Lightbox 同一元件） |
| ⋯【繼續取這支的圖】 | 跳精靈第二步，已收藏格標示 |

| ⋯【刪除整支收藏】 | 確認框明示張數與手動補圖數 → 刪 shot／shot_tag／遞減彙總／`{videoId}/` 前綴列舉刪 R2／刪 video 列 → 導回首頁 |

**狀態**：影片被刪或轉私人時 iframe 失效，但圖資與縮圖仍在（不得整頁失敗）

**量級**：單片 shot 數，通常 < 50，可一次載完。

### 10. 帳號／設定

| 顯示 | 來源 |
|---|---|
| 帳號列（頭像／名稱／email） | Access JWT 或 GIS token，**不得寫死在 HTML** |
| ★ 一句「目前收藏 13 張，來自 11 支影片。」 | 需 shot 總數 ＋ distinct video 數 → 新端點（原型另有「本月新增」） |
| 過濾相似強度（高／中／低） | ★ **規格資料模型沒有任何地方能存**。原型存 localStorage |
| AI 分析區間（往前 N 秒／往後 M 秒） | ★ 同上。原型連 localStorage 都沒存，重整就回預設 |
| 標籤管理（改名／改 kind／別名／刪除） | ★ **規格第十一節的十四個階段完全沒有這一面**。改名與刪除會牽動既有 `shot_tag` 關聯與 `facet_month_agg` |
| 縮圖服務：【重新抓取缺少的縮圖】＋「目前沒有缺少的縮圖」 | ★ 同上，十四階段沒有。需要「缺圖數」查詢與批次補抓作業 |
| 【登出】 | 破壞性樣式，置於最底 |

**量級**：標籤數百；補抓作業的量取決於降級期間入庫的影片數。

## 三、三個最大的互斥項：選項展開

### D-1 認證方案

| 選項 | 內容 | 代價 |
|---|---|---|
| **A** | **Cloudflare Access ＋ Google IdP**（規格第九節現行選擇） | 應用端約 10 行程式碼、攔截在邊緣、免費 50 人。**但手冊 §一的 11 條驗收項大部分不成立**：登入頁不是我們的、按鈕樣式管不到、「登入中過場」「登入後回到原本要去的地方」「已登入就看不到登入頁」全數失效；`login.html`／`auth.js` 直接作廢 |
| **B** | **站內 Google 登入頁**（手冊描述的樣子），但 API 不驗證 | ❌ 不成立。任何人開 devtools `fetch('/api/shots')` 就能讀寫資料庫。規格第九節已論證，此項不列為真正選項 |
| **C** | **GIS ＋ 後端驗證 token** | 手冊 §一 11 條**全部成立**，安全性等同 A（每條 API 驗一次 JWT）。代價是應用端多一個「驗簽章 ＋ 快取 Google 公鑰 ＋ 處理過期」的模組。**這筆工作不是白做的** —— 規格第十八節已寫明 v3 自架版沒有 Access 可用、屆時本來就要換成 C |

> C 是「最壞情況不劣於 spec」的那條路：安全性與 A 相同，UI 與手冊相同，多出的程式碼是 v3 遲早要寫的。
> 但它不是零成本，仍需你們裁決。

### D-2 取圖第二步的收斂

### D-3 首頁欄數隨當月張數變
